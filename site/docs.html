Cloud OS Documentation

A practical guide to installing, operating and securing Cloud OS. Everything here is readable directly on the website.

Installation

Cloud OS supports Windows 10/11 and Linux. The installer handles Python/application prerequisites where supported.

Windows

irm https://raw.githubusercontent.com/nadeemmhdm/cloud-os/main/install.ps1 | iex

Run PowerShell as Administrator. Current automatic startup is a current-user Task Scheduler entry triggered at logon, not a pre-login Windows service.

Linux

curl -fsSL https://raw.githubusercontent.com/nadeemmhdm/cloud-os/main/install.sh | bash

Debian/Ubuntu and Fedora-family prerequisite installation is supported. The development installer does not enable Cloud OS as a root service.

Security model

Passwords use salted PBKDF2-derived hashes. Sessions expire. Web and SSH password authentication use persistent progressive cooldowns against repeated guessing. Protected management endpoints enforce permissions. File paths are resolved against the configured storage root. Browser terminal access is high trust because commands inherit the Cloud OS process privileges.

AI provider keys are server-side secrets. Never commit credentials, tunnel tokens, session cookies or private keys. Use strong unique passwords and grant terminal access only to trusted operators.

Remote access

For remote deployment, use authenticated TLS access. A Cloudflare Tunnel can transport traffic without router port forwarding, but it does not replace Cloud OS authentication/RBAC. Additional access controls/MFA are recommended for Internet-facing use.

AI Help

Cloud OS can use Gemini, OpenAI, Claude or Ollama Cloud. Only one configured provider is required. The helper selects relevant local project documentation and supplies it as reference context when diagnosing Cloud OS errors. This does not train or fine-tune the provider model.

Updates and rollback

cloud-os update-check cloud-os update

The default update channel is the latest GitHub Release. Development builds can explicitly use cloud-os update --source main. The updater displays real operation stages, refuses a dirty source checkout, and attempts to restore the previous Git revision if package installation fails. A successful update reports the installed version and revision. Signed/checksummed production artifacts remain future hardening work.

Uninstall

cloud-os uninstall asks for confirmation and preserves configuration, backups and configured storage by default. Use --yes to skip confirmation. Use --purge-data only when permanent data deletion is intended.

Troubleshooting

Start with:

cloud-os doctor

Check Python, storage permissions, configured port, Cloudflare/SSH tooling and process state. If local access works but remote access does not, inspect the tunnel/reverse proxy instead of opening the development server directly. For a reported code, use the searchable Error Code Library.
