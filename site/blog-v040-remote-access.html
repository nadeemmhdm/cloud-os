Cloud OS v0.4.0: remote access gets simpler

A closer look at the safer update lifecycle, dashboard-managed Cloudflare connector workflow, and the boundaries that keep remote access understandable.

Cloud OS TeamEngineering & project updates
In this articleA more predictable update lifecycleConnecting an existing tunnelDiagnostics where they matterWhat Cloud OS does not automate

A more predictable update lifecycle

Cloud OS v0.4.0 focuses on making day-to-day server ownership more predictable. The update flow exposes clear stages for checking, fetching, preparing, installing and verifying an update. If installation fails, rollback behavior remains explicit rather than leaving the operator guessing which version is active.

Connecting an existing tunnel

Remote access gets a simpler dashboard workflow. An Owner or Admin can connect an existing remotely-managed Cloudflare Tunnel using its tunnel token. Cloud OS stores the token on the server and does not return the raw secret through the status API or dashboard after configuration.

Diagnostics where they matter

The Integrations page reports connector state, the detected cloudflared version and a redacted startup diagnostic when the connector cannot remain running. This gives operators useful evidence for tunnel failures without encouraging credentials to be copied into screenshots or support messages.

What Cloud OS does not automate

Cloud OS does not create Cloudflare DNS records or Published Application routes. The public hostname still needs to be configured for the intended tunnel and local origin. Internet-facing deployments should also use an additional access layer such as MFA.
