Why Cloud OS keeps privileged operations explicit

Browser terminals are powerful. Cloud OS makes privilege boundaries visible through RBAC, audit events and host operating-system controls.

The terminal is a high-trust capability

A browser terminal can be one of the most powerful parts of a server dashboard, so Cloud OS treats it as a high-trust capability rather than an ordinary convenience feature.

Roles before commands

Role-based access control separates Owner, Admin, Operator, Member and Viewer capabilities. Terminal execution is available only to roles with terminal permission, while audit events record activity without storing raw terminal command text in the audit entry.

No silent privilege bypass

Cloud OS avoids silently bypassing operating-system privilege controls. On Windows, a browser request cannot bypass UAC to turn an unelevated Cloud OS process into an Administrator shell. On Linux, privileged requests depend on the host's configured sudo behavior.

Authentication is part of the boundary

Web and SSH password authentication use persistent progressive cooldowns after repeated failures. The objective is to make sensitive access deliberate and observable rather than hiding escalation behind the dashboard.
